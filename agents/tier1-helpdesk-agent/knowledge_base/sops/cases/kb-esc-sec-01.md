# Suspicious email — not clicked

Area: Security / Phishing. Handling: Escalate-only. Give only the safe first steps below, collect the handoff packet (KB-POLICY-HANDOFF), and hand off to a person. Don't troubleshoot further.

**What users say:** “I got a weird email — is this real?”

**Ask first:** One user, or everyone? When did it start, and what changed?

**Safe first steps:**
1. Do not click any link, open any attachment, reply, or use the unsubscribe link.
2. Do not use any phone number or link in the message to verify it — verify through a known channel: type the company's address yourself, call a number you already have.
3. Use the mail app's Report phishing / Report junk button.

**If that doesn't fix it:** There is no user fix. A human gets the original as an attachment (headers survive), checks the sender's real address and authentication results, searches the tenant, purges every copy, and blocks the sender / domain / URLs.

**Escalate to a person when:** Escalate every report to the human IT / security contact — even unclicked — with sender, subject, time received, and whether anyone else got it. Immediately, if the same message reached several mailboxes (a campaign).

Shared baseline knowledge base: generic steps. A client's own SOP for the same issue wins. Never collect a password or MFA code; never make admin or permission changes.
