Hard guardrails — encoded in every answer

The agent guides by chat only. The user does the clicking; the agent changes nothing on any system. Where a fix requires one of these, the step is not a step — it's an escalation, after a human verifies identity.

  • Never collect a password — current, new, temporary, or an MFA code
  • Never make admin or permission changes
  • Never start remote access on its own
  • Never delete data
  • Never guess — an unmatched error means escalate
  • Never ask for, paste, or store PHI in chat

Case library — what to put in the RAG

Two questions come first in every case: “One user, or everyone?” and “When did it start — what changed?” Scope decides everything. Offer steps in the user's language, but quote on-screen error text in English exactly as shown — never translate error codes. Onboarding & offboarding — a request, not a fix

The agent never creates accounts, assigns licences, sets passwords, or grants access. It collects a complete request and hands it to the human / IT owner. If the manager, role, or access list is missing, it asks and waits — it does not guess access.

New starter — collect before day one

  • Full name (preferred display name), start date, manager, role / department
  • Work location: office / home / both; employment or contractor status
  • Systems the role needs: email, apps, shared drives, printers, phone extension, VPN
  • Equipment: laptop/desktop, monitor, dock, headset
  • Manager's approval for access — plus a “same access as [named colleague in the same role]” reference, never “give them everything”

Human then: creates a named account (never a shared login), assigns the licence, enrols MFA with the user, adds role groups/drives, sets up the phone extension, and gives a one-page welcome sheet. Every account documented — without writing down any password.

Leaver — collect & act same day

  • Name, last day and timing, manager
  • Equipment to return
  • Email / file ownership to transfer, and who takes over shared mailboxes and files

Human then: disables the account the same day, revokes sessions, removes VPN/app access and MFA tokens, transfers ownership, recovers the licence, and verifies access is gone. Never leave a leaver's account active “just in case,” and never reuse their password or share their login with a replacement.

Day-one login problems: collect which step fails, the exact error text, and whether MFA enrolment was completed. If the account doesn't exist or the licence is missing, it's an admin fix, not a user fix.

RGV field notes

Clinics: any case touching patient systems, the EHR, or PHI is an immediate escalation — never troubleshoot PHI access in chat.

Contractors / logistics: field, mobile, shared printer/scanner, and VPN-from-a-job-site cases are common — always ask where the user is (office, home, job site, truck) and whether they're on Wi-Fi, mobile data, or a hotspot.

Professional services: Outlook / Teams / shared-drive cases dominate — “Can a colleague in the same role open it?” is the fastest scope check.

Cases that must go to a human IT professional

If a case appears here, the agent does not attempt a fix. It gives only the safe first-aid listed, collects the packet, and hands off immediately — with urgency and a named human contact. That contact must be configured per client; it isn't named yet (see Open questions).

How to use forums as a research source — without copying

Rule for the RAG build: every agent answer must be traceable to vendor help or to a human-approved runbook synthesised from forums. No answer should trace only to a single anonymous forum post.

Do

  • Search by symptom + exact error text, in English and Spanish: site:community.spiceworks.com Outlook "cannot send", site:reddit.com/r/techsupport "printer offline", site:serverfault.com "shared drive access denied", site:superuser.com "second monitor not detected"
  • Sort by most-viewed / most-upvoted; filter to the last 12–24 months — Windows 11 and Microsoft 365 change fast, and a 2019 printer-driver answer can be wrong now
  • Triangulate every step: forum answer → vendor-published help → a second independent thread. Vendor docs win on product behaviour; forums win on how users describe it and what fails in practice
  • Paraphrase and synthesise into your own runbook. Record the idea (queue → spooler → driver), not the poster's sentences. Keep a source link per entry
  • Note date, product version, and scope (one user vs whole office) on every note
  • Strip all personal data — never ingest usernames, emails, log excerpts, screenshots, or anything that could be a password, PHI, or customer data
  • Prefer accepted / highly-voted Stack Exchange answers and threads marked solved or with a staff reply

Do not

  • Do not paste or ingest forum posts verbatim into a RAG corpus or a commercial answer — quality risk and legal risk
  • Do not scrape Reddit. Its User Agreement prohibits unauthorised scraping and commercial exploitation; Reddit has litigated unauthorised scraping for AI training (Reddit v. Anthropic; Reddit v. SerpAPI, S.D.N.Y. 2026). Scale use needs Reddit's licensed Data API / a commercial agreement — get legal advice first
  • Do not bulk-ingest Stack Exchange verbatim. Posts are CC BY-SA 4.0: reuse requires author attribution, a link to the original question, and share-alike — a regime that doesn't map cleanly onto an AI answer
  • Do not treat Spiceworks, Reddit, Tom's Hardware, or BleepingComputer posts as authoritative — peer advice, sometimes wrong, sometimes for a different version
  • Never let the agent quote a forum post as vendor guidance, or run a forum-suggested registry / command-line fix unsupervised
  • Do not use BleepingComputer malware-log threads as a live playbook

What to gather — and what it costs

Do you need to pay for any information sources? No. Every forum and vendor source in this base is free to read. The gathering work is time, not licences — your own procedures, plus each client's specifics. Paid access only enters the picture if you ever want Reddit or Stack Exchange content at scale under a commercial licence (see the research rules) — research reading needs none of it.

1 · Your own playbook (the core)

  • One short entry per case in the library above: symptom in the user's words, steps in order, the “if step 1 fails” branch, and the escalation point
  • The 15 must-escalate triggers and the handoff packet
  • Guardrails: what the agent must never do, the escalation contact, business hours, and the “get a person” keywords

2 · Per-company info (never reused across clients)

  • Email / identity platform (Microsoft 365 / Entra ID vs Google Workspace vs other), VPN product, printer and PC vendors
  • Line-of-business apps — EHR, dispatch, accounting — and who owns each
  • Wi-Fi names, shared-drive paths, self-service password-reset link, IT approver
  • Their policy on what the agent must never touch, and any internal guides they already have

The runbook steps here are generic — per-client versions will differ. This per-client configuration is still an open item (below).

3 · Public vendor docs (free)

  • Microsoft Support, Google Workspace Help, Apple Support, printer / PC vendor support
  • Retrieve the relevant passage at answer time, cite the source, and link out — don't copy whole articles in. That keeps answers current and licensing clean

4 · Past questions & fixes (builds itself)

  • Every resolved conversation becomes future knowledge
  • Questions the agent couldn't answer are the gap list — draft new entries from them, human-approved before they go live

Open questions — flagged plainly

  1. Escalation contact / channel is not named. The human IT professional's name, phone, email, ticketing system, and hours aren't set yet. The agent cannot hand off safely without this configured per client.
  2. Client stack is unknown per business — email/identity platform, VPN, printer/PC vendors, and line-of-business apps. Runbook steps here are generic until each client is configured.
  3. Some forum URLs need a live check before going in a customer-facing list (Reddit, Server Fault, Super User, Stack Overflow, Tom's Hardware homepages came via search-result pages).
  4. CISA / FTC phishing wording was corroborated through secondary summaries, not the primary cisa.gov / consumer.ftc.gov pages — verify exact report routes before putting them in agent wording.
  5. HIPAA 2026 rule change is proposed, not final. The reported tightening (72-hour notification, mandatory MFA/encryption) must not be stated as current law — re-check HHS/OCR before any clinic-facing wording.
  6. Forum access rules change — free-to-read / account-to-post status is as of 13 Nov 2026, and Apple shows a forum can close on ~10 days' notice. Re-verify before launch.

Clinics — HIPAA, in brief

A breach is presumed unless a documented four-factor risk assessment shows a low probability of compromise. Individuals must be notified without unreasonable delay and no later than 60 days after discovery; HHS must be notified too (500+ records within 60 days; under 500 logged and reported within 60 days after year-end). A vendor handling ePHI needs a signed Business Associate Agreement (BAA) before handling it — confirm the AI / hosting arrangement is covered before any clinic data touches the tool.
